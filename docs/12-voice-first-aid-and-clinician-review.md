# Voice, first aid and clinician review

These are three different tools. They do not turn NeighbourAid into an
emergency dispatch centre or an AI doctor. Call **112** for immediate danger;
never wait for a volunteer or a private review to reply.

## What is available

| Tool | Where | What it does | Important limit |
|---|---|---|---|
| Voice interview | Report crisis → Report by voice | Asks what happened, optionally asks for a nearby landmark, builds editable text | You confirm category, GPS and the report; nothing is automatically sent |
| Dictation | Crisis description, paid-help details, private review question | Adds the final transcript to your draft | Provider errors are shown; there is always a typing fallback |
| First-aid guide | Report crisis, Safety, medical/fire/accident share pages | Safety check, adult CPR gate, heavy external bleeding and small heat-burn guidance | Reference-based English/Hindi copy; not yet clinically reviewed for this app |
| Private clinician review | Safety → Private clinician review | A consenting adult asks their own non-emergency question; an approved clinician records a referral next step | No emergency response promise, diagnosis, prescription or automatic licence verification |

### Voice flow

```text
Tap Report by voice → choose language → tap Speak now
  → question is shown / spoken when a suitable voice is installed
  → device speech service returns a transcript
  → review/edit words + choose report type → Add to report
  → confirm GPS/photo/details in the normal form → send yourself
```

The selectable recognition locales are English, Hindi, Bengali, Marathi,
Telugu, Tamil, Gujarati, Punjabi, Kannada, Malayalam and Odia. Interview prompts
are present in all eleven. This is a requested locale, **not a guarantee** that
every browser/phone supports it or understands mixed-language speech. Install
the provider's language packs where needed. Native-speaker review is still
needed for the new translated prompts.

Android uses a user-triggered system speech dialog, not a custom always-on
microphone. Browser builds use Web Speech where available on HTTPS. Android
read-aloud uses its TTS engine; web read-aloud requires a matching installed
voice. Missing voices leave the written question available. Changing language,
closing the dialog, or cancelling invalidates old callbacks. The assistant
does not restart the microphone or submit a report by itself.

Speech providers may send audio off-device. NeighbourAid does not upload or
store the recording, but anonymity cannot be promised to the speech provider.
Type instead if the report must remain anonymous. Dictation appends rather
than silently truncating: if the combined text exceeds the form's limit,
review and shorten it before sending.

## First-aid boundary

```text
Safe and able to help?
  ├─ no / unsure → stay clear, call 112, trained help
  └─ yes → manually choose a situation
       ├─ collapse → adult? → normal breathing?
       │    ├─ child / unsure → dispatcher, no adult CPR instructions
       │    ├─ normal → no compressions, dispatcher + monitor breathing
       │    └─ not normal / gasping → adult CPR reference steps
       ├─ heavy external bleeding → pressure/reference steps
       ├─ burn → small heat burn? otherwise urgent professional help
       └─ other / unsure → dispatcher, no guessed treatment
```

All steps remain visible together; paging highlights/read-aloud must not delay
urgent assistance. There is no “patient cured” or “treatment complete” action.
112 stays available before any answers. Demo builds disable real calls.
Scene answers stay in memory, not localStorage, analytics or MongoDB. The
bundled guide can open without the backend; external source links and speech
services may still need Internet access.

Medical instructions are not machine-translated, selected from an AI category,
or generated by the local LLM. Guide copy is English/Hindi with an explicit
English fallback for other interface languages. Source review date in code is
2026-10-06; it is **not** a clinical sign-off. Qualified clinicians and native
reviewers must check the actual app wording/branching before a medical launch.

Original references: [St John Ambulance CPR](https://www.sja.org.uk/first-aid-advice/cpr/),
[American Red Cross CPR](https://www.redcross.org/take-a-class/cpr/performing-cpr/cpr-steps),
[St John Ambulance bleeding](https://www.sja.org.uk/first-aid-advice/severe-bleeding/),
[American Red Cross bleeding](https://www.redcross.org/take-a-class/resources/learn-first-aid/bleeding-life-threatening-external),
[NHS burns](https://www.nhs.uk/conditions/burns-and-scalds/),
[London & South East Burn Network](https://www.lsebn.nhs.uk/patient-information-3).
India's emergency number is documented by [MHA ERSS](https://www.mha.gov.in/en/divisionofmha/women-safety-division/emergency-response-support-system-erss).

## Clinician access: operator approval, not self-signup

An existing reporter/volunteer account can receive an independent clinician
permission. Registering as “doctor”, adding a skill or changing a JWT role
does not grant it. Every desk read/write checks the current MongoDB approval
and validity, so expiration/revocation does not wait for a token to expire.

Before approval, the operator must check identity, active registration with
the relevant medical council, suitability for the role, and the clinician's
consent. This is a manual process: the CLI **does not** check any registry.
Agree privacy, escalation, staffing and professional responsibility before
accepting real questions. This prototype is not a claim of telemedicine/legal
compliance; get qualified medical, privacy and regulatory review first.

The clinician's existing account ID is available from their profile API;
use the actual MongoDB user ID, not their email or registration number.
From `backend/` on the configured local environment:

```powershell
.\venv\Scripts\python.exe -m scripts.clinician_access approve --user-id "ACTUAL_USER_ID" --name "ACTUAL_CLINICIAN_NAME" --council "ACTUAL_COUNCIL" --registration "ACTUAL_REGISTRATION" --reviewed-by "OPERATOR_NAME" --valid-days 30 --credentials-checked
.\venv\Scripts\python.exe -m scripts.clinician_access revoke --user-id "ACTUAL_USER_ID" --reviewed-by "OPERATOR_NAME"
```

For the Docker-managed database, run the equivalent command inside the local
API container after rebuilding the image. From the repository root:

```powershell
docker compose -f deploy/laptop/docker-compose.yml exec api python -m scripts.clinician_access --help
```

Replace `--help` with the approval/revocation arguments above only after the
checks are complete. Do not recreate or delete database volumes to enrol a
doctor. Approval lasts 1–90 days (default 30); recheck before renewal.
No accounts or credentials were enrolled by implementing this feature.

### Private request flow

| State | Who can see medical text? | What it means |
|---|---|---|
| Pending | Requester only | Submitted, not reviewed; the clinician queue shows timestamps only |
| Claimed | Requester and assigned, currently approved clinician | One clinician has accepted responsibility; no response yet |
| Reviewed | Requester and that clinician | Attributed response with name, council, registration and timestamp, not a diagnosis/“safe” certificate |
| Deleted / expired | Not returned by the API | Requester can delete; all reads/writes enforce expiry even before Mongo TTL cleanup |

Responses allow emergency referral, an in-person assessment or a request for
more information. A clinician cannot review their own question, another
clinician's assignment, a withdrawn/expired case, or overwrite a completed
response. Claim/respond updates are atomic. Pending/claimed requests have a
soft per-account cap of three in addition to existing write rate limits.

Questions require explicit adult-self, non-emergency and sharing consent.
They never enter public alerts, volunteer WebSockets, push payloads or an AI
inference service. Records expire after 72 hours from submission, including
completed responses. Mongo TTL removal is asynchronous; application queries
also exclude expired records. Deletion does not erase copies a human already
read or older operator backups: set an appropriate backup retention policy.
There is no field-level encryption, closed-app reply notification, automatic
reassignment after a clinician is revoked, or promised response time.
The requester can delete/repost a stalled request or seek in-person care.
The demo never sends these questions to real doctors.

## Maintainer checks

Use Node 22/npm 10 for CI-compatible lockfile changes. A newer local npm's
dry-run can pass while Node 22's clean install rejects missing nested entries;
this happened with `brace-expansion`/`balanced-match`. Do not bypass `npm ci`
with `--legacy-peer-deps`; commit the corrected lockfile with dependency edits.

Run frontend lint/tests/tool tests, backend tests, `mobile:sync`, and Android
plugin unit tests plus an APK build. Test actual microphones/voice packs and
two signed app versions on a phone separately. Viewport screenshots do not
prove speech recognition works on a physical device.

The approved brand source is `frontend/assets/logo.png`. Run
`npm run assets:generate` in `frontend/` to package web/demo/PPT icons and
Android launcher/splash resources. Do not hand-edit generated Android files.
